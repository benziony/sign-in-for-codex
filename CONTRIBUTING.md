# Contributing

Thank you for helping make human sign-in handoffs safer and less awkward.

1. Discuss behavior or security-boundary changes in an issue first.
2. Use only synthetic `example.test` provider data in tests and reports.
3. Run `npm ci`, `npm run check`, and `npm run audit:public`.
4. Explain what changed, which sign-in flow it serves, and how failure remains
   safe.

Never include real provider URLs, codes, cookies, credentials, tokens, private
repository material, or authentication logs in an issue or pull request. Report
vulnerabilities through the private process in [SECURITY.md](SECURITY.md).
